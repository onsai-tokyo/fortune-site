## 質問への回答・未実装

5. 続きの変更で、新Webのログイン画面にメール＋パスワードとGoogleを追加。コードログインは維持。メール確認後の登録設定画面に任意のパスワード設定を追加し、保存先はその時点の認証済みユーザーに固定。パスワードをアプリのストレージに保存しない。Googleはログイン専用で匿名データの自動統合は行わず、切替前の確認を必須とする。Google callbackは `/restore?oauth=1` に固定し、本棚へ戻す。

   本番設定の確認時点ではGoogleは有効、Redirect URLsは空、Site URLはiOS用の `fatelab://auth/callback`。ユーザーの追加承認後、`https://fate-lab.com/restore?oauth=1` を許可リストに1件追加し、表示を確認。Site URLやiOSは変更していない。manual linkingも無効のまま。実Googleアカウントでのログイン完了はユーザーによる確認が必要。
7. デモの性格は4章に省略してある。本番は `/api/web/reading/:id/cards` の応答から、本人向け・非ロック・年表と命式以外のカードを章に変換するため、4章に制限していない。今回本番アカウントの章数は再取得していない。
11. 「20万通り以上」はソースの検索では算定根拠を確認できず、未掲載。何の組合せ数なのか、重複や未生成部分をどう数えるかの確認が必要。数字と「全員が必ず別文章」を同一視しない。
15. 相手単独の性格を読む専用画面は現在のWebにない。現在表示しているのはふたりの年ごとの関係。相手の性格API・権限・情報量を確認して追加する別作業が残る。
17. 無料の性格・年表は支払い不要。AI相談ブックはWeb用の有効な冊数が必要。デモの残り2冊は見本のみ。本番は購入または管理者付与分を使用し、現在は販売準備中なので新規購入不可。残高ゼロから画面だけで冊数を増やすものではない。今回そのサーバー処理は変更していない。

## 保存のコスト

`reading_saves` に保存するのはuser_id、save_key、日時であり、鑑定本文を毎回複製しない。同じアカウント・保存キーは主キーで重複しない。保存操作によるAI生成料は発生しない。

仮にインデックス等を含め1件0.3〜1KBと置くと、100万保存で約0.3〜1GB。これは実測値ではなく容量計画用の概算。Supabase標準gp3のProでは8GB込み、超過ディスクは$0.125/GB/月。したがって保存参照だけの容量コストは小さい一方、実請求にはプラン基本料、ディスク確保量、MAU、計算リソース、通信量、元の鑑定本文なども関わる。本番のプランや使用量を今回は確認していないため、請求額は断定しない。
