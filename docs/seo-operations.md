# Fate Lab SEO運用手順

最終更新日: 2026-11-19

## ブランド表記

外部プロフィール、プレスリリース、動画説明欄では次の表記を統一する。

- サービス名: Fate Lab（フェイトラボ）
- URL: https://fate-lab.com/
- 運営: 温齋株式会社
- 説明: 東洋・西洋・インドの9つの占術を固定ルールで統合する、生年月日の無料オンライン占い

`Fortune Lab`、`fortune-lab`、`fotune-lab` は自社サービス名として使用しない。

## 優先して整備する外部プロフィール

1. 温齋株式会社の公式サイトからFate Labへ、サービス名をリンク文言にして掲載する。
2. X、Instagram、YouTube、noteなど、実際に運用できる公式アカウントだけを作成する。
3. 各プロフィールでサービス名、説明、URL、ロゴを統一する。
4. プレスリリースまたは開発ストーリーを公開し、計算の再現性と9占術の統合方法を説明する。
5. 占術家・編集者・利用者に、実際に利用したうえでの率直なレビューや紹介を依頼する。

リンク購入、大量相互リンク、無関係なディレクトリへの一括登録は行わない。

## プレスリリース骨子

- 見出し: 9つの占術を固定ルールで統合する無料生年月日占い「Fate Lab」を公開
- 課題: 占いサイトごとに結果や根拠が異なり、利用者が比較しにくい
- 特徴: 同じ入力なら同じ計算結果、時刻不明時は推測しない、複数占術の一致点を優先
- 対応占術: 四柱推命、算命学、納音、宿曜、九星気学、数秘術、紫微斗数、西洋占星術、インド占星術
- 運営会社と問い合わせ先
- サービスURLとOG画像

## 毎週のSearch Console確認

1. 過去28日とその前の28日を比較する。
2. 表示回数、クリック数、CTR、平均掲載順位をページ・検索語別に確認する。
3. 掲載順位8〜20位で表示回数の多いページを優先して加筆する。
4. 順位が高くCTRが低いページは、検索意図に合わせてタイトルと説明文を改善する。
5. インデックス未登録、クロールエラー、Core Web Vitals不良を確認する。
6. 実質的に更新したURLだけ再クロールを申請する。

### CSVから改善候補を自動抽出する

Search Consoleの「検索結果」から、検索語とページを含むCSVをエクスポートし、次を実行する。

```bash
node scripts/analyze-search-console.mjs ~/Downloads/fate-lab-search-console.csv
```

`reports/search-console-YYYY-MM-DD.md`へ、次の順で改善候補が出力される。

1. 掲載順位8〜30位で表示回数が多い検索語
2. 10位以内なのに想定よりCTRが低い検索語
3. 4〜7位で上位3件を狙える検索語
4. 現状を維持すべき1〜3位の検索語

ページ列が入ったCSVを推奨する。Search Consoleの画面で「検索キーワード」と「ページ」を同時に出力できない場合は、優先ページを選択してから検索キーワードをエクスポートする。

## 自然検索からの鑑定完了を入口別に見る（GA4）

1. 運営者が「管理 → データの表示 → カスタム定義」で、以下の2件を確認する。未登録のものをイベントスコープで作成する。すでに登録済みのものは既存の表示名を使う。

   | ディメンション名の例 | イベント パラメータ |
   | --- | --- |
   | Fate Lab の入口の種類 | `fl_landing_group` |
   | Fate Lab の流入元 | `fl_traffic_source` |

2. 「探索 → 自由形式」で、上記2つと「イベント名」をディメンションとしてインポートする。指標には「イベント数」を追加する。
3. 行に「Fate Lab の入口の種類」、列に「イベント名」、値に「イベント数」を置く。
4. フィルタを2つ指定する。流入元は `organic_search` に完全一致、イベント名は正規表現 `^(self_reading_complete|couple_reading_complete)$` に一致とする。これで個人鑑定と相性鑑定の完了回数を並べられる。テスト操作の `qa_` イベントは集計から外れる。
5. 本番反映とカスタム定義の登録が両方済んだ後の期間を選ぶ。新しい定義が探索で使えるまで通常24〜48時間かかる。必要に応じて「総ユーザー数」も値に加えると、同じ人が複数回完了した場合を区別できる。

入口はセッションで最初に開いたページで決まる。たとえば無料計算から相性占いへ移って完了した場合、相性鑑定の列の `tool` 行に1回加わる。

| 入口の種類 | 最初に開いたページ |
| --- | --- |
| `top` | トップ、または同じトップを表示するThreads告知用URL |
| `tool` | 無料計算の一覧・各ツール |
| `guide` | 記事一覧・解説記事・日干や通変星などの一覧ガイド |
| `series` | 日干・通変星・十二運の個別解説 |
| `uranai` | 復縁・片思い・相手の気持ち・婚期を占うページ |
| `fortune` | 公開済みの年別運勢の総合・個別記事（公開後から集計） |
| `couple` | 相性占いトップ |
| `other` | クーポン、結果画面、分類対象外の入口など |

参考：[イベントスコープのカスタムディメンション](https://support.google.com/analytics/answer/14239696?hl=ja) ／ [自由形式の探索](https://support.google.com/analytics/answer/9327972?hl=ja)

## 月次コンテンツ監査

- 計算例、境界条件、独自検証のいずれかが記事に含まれているか
- 記事の主張と実装の計算仕様が一致しているか
- 類似記事同士で検索意図が重複していないか
- 古い記事の日付だけを変更していないか
- 関連記事と無料鑑定へのリンクが機能しているか
- 医療、法律、金融、採用を占いだけで判断させる表現がないか

## 計算ページと解説記事の役割（2026-11-23）

検索語が複数ページに表示されただけで、検索順位への悪影響や記事統合の必要性を判断しない。特に表示回数が少ない検索語とブランド検索は、タイトル変更や統合の根拠を分けて考える。

| ページ | 主に答える疑問 | 次に案内するページ |
| --- | --- | --- |
| `/` | FateLabで何を無料鑑定できるか | 項目別の無料計算 |
| `/tools/sanmeigaku-calculator` | 自分の人体星図・十大主星・十二大従星・天中殺を計算したい | 星の意味・位置別の解説 |
| `/guides/sanmeigaku` | 算命学の全体像と基本の読み方を知りたい | 無料自動計算、星一覧 |
| `/guides/sanmeigaku-stars` | 結果に出た星の意味を知りたい | 未計算なら無料自動計算 |
| `/couple` | 生年月日から二人の相性を鑑定したい | 鑑定結果 |
| `/guides/compatibility` | 二人の命式で何を比較するか知りたい | 相性鑑定、結婚生活を考える解説 |
| `/guides/marriage-compatibility` | 今の恋人との結婚生活や話し合う条件を整理したい | 婚期の解説、二人の命式計算 |
| `/guides/marriage-timing` | 自分の命式・大運・年運から結婚時期の候補を読む手順を知りたい | 結婚相性の解説、自分の日柱の計算 |

### タイトルと導線を変更した後の比較

- 変更前に、検索タイプ・国フィルター・データ確定状況・集計期間を記録する。全世界の数字と日本限定の数字を混ぜない。
- 直近の確定済み28日間と、その前の28日間を同じ条件で取得する。公開後の評価は本番反映日を起点に、変更前後の同じ長さの確定済み期間で行う。
- サイト全体、ページ別、検索語とページの組み合わせ、デバイス別をそれぞれ取得する。検索語別に省略されるデータがあるため、行の合計をサイト全体の実績として扱わない。
- CTRは検索語・デバイス・掲載順位の変化と一緒に読む。順位が低いページの0クリックを、タイトルだけの問題と判断しない。
- 同じ検索語でトップと計算ページ、鑑定ページと解説ページが表示された場合は、意図に合う専用ページの表示回数・順位と、既存の鑑定完了計測を確認する。
- 少数の表示やクリックだけで変更を繰り返さず、判断材料が足りなければ観察を継続する。

## 読者向け計算例と制作情報の確認（2026-11-23）

- 日干・五行・適職・数秘術・出生時刻不明・節入りの記事は、冒頭から内容に合う無料計算へ案内する。リンク先やURLに生年月日などを含めない。
- 出生時刻の有無を比較する例は `frontend/reader-evidence-copy.js` にまとめる。計算値は `frontend/scripts/article-data/reader-evidence.test.ts` で公開計算と共通の関数に照合する。
- 計算方針ページでは、再現用の入力条件、結果、詳しい解説へのリンクを併記する。国立天文台の暦資料は節気時刻の参照元として示し、占術の解釈や的中率の根拠として扱わない。
- 全解説記事から制作主体・制作手順・計算方針に進めるようにする。制作情報の共通リンクだけの変更で、全記事の更新日を一斉に変更しない。
- 個人の著者名・資格・監修実績を確認なしで追加しない。情報ページの更新日は本文を実際に変更した日を記録し、過去の公開日を推定しない。

計算例の照合は backend ディレクトリで次を実行する。

```bash
node --import tsx --test ../frontend/scripts/article-data/reader-evidence.test.ts
```
