# 旧閲覧URLの互換対応（2026-10-18、ローカルのみ）

## 続報：旧ログインとアカウント境界

- `/legacy/login` を追加。既存Supabaseのメール/パスワードとGoogle認証だけを使う。旧閲覧ページから案内する。新規登録・パスワードリセット・購入のAPIは呼ばない。iOSファイルや本番の認証設定は変更しない。
- Googleは従来と同じSupabase OAuth。以前のGoogleアカウントを選ぶよう明示した。**OAuth側の仕様により、未登録のGoogleアカウントを選ぶと新アカウントが作られる可能性は残る**。直接signUpを呼ばないことと、認証基盤での新規作成禁止は同義ではない。
- 戻り先は既存 `safeReturnTo` を通したうえで `/r/<token>` / `/reading/<id>` だけに限定。query/hashは捨て、旧checkoutや新規作成・決済画面へ戻さない。外部URL、二重エンコード、バックスラッシュ、認証ページへのループはトップへ戻す。
- 通常の見本データビルドではログインを無効化。REMOTE合成ビルドでのみテストする。本物のパスワード・メール・認証コードは使用していない。
- Web AppStateで所有者変更時に旧プロフィール・本棚・冊数・相手・下書き等を空にし、旧所有者または古いトークンで開始した読み込み結果をrevision照合で破棄する。起動時getSessionが後から返って認証イベントを上書きする競合も防止。
- REMOTEの下書きはユーザーID別キーのみを読む/書く。共有キーからの自動コピーは廃止し、保存先を非同期getUserで後から決めない。既存の共有キーの値は削除しないが、所属が分からないので特定ユーザーへ自動移行しない。

## 実装

- `/s/:shareId`：既存の公開共有APIから一言要約・一致の印・五行だけを表示。出生情報は表示しない。削除済み/無効な共有はエラー表示。
- `/r/:secretToken`：既存の本人限定APIでIDを解決し、認証付きcards APIの投影済み本文だけを表示。トークンだけでは公開閲覧できない。
- `/reading/:conversationId`：認証付き本人限定APIで取得し、投影済みカード・保存済みの質問/回答を表示。他人の履歴は拒否。
- `/reading?conversation=...`：対応する閲覧ページへ転送。旧checkout引数は引き継がず、購入や自動生成は起動しない。
- `/reading/new` は入力へ、`/reading/history` は新しい本棚へ案内。
- 上記3系列をトップへ転送していた両方のVercel設定を修正。未デプロイ。
- 全ページ閲覧専用。カードロックを解除せず、旧購入・質問送信・再生成は復元しない。raw report_textを表示せず、ロックされたカードの要約/本文も表示しない。
- ログアウト/アカウント変更時に本文を消し、古い非同期応答を破棄。SDK通知に加え別タブの認証storage削除/別ユーザーへの差し替えも検出する。
- URL内トークンがGAのSPA履歴計測に流れないよう、**新Web SPAのAnalytics初期化を停止**。閲覧URLはnoindex/nofollow、全SPAにno-referrerを設定。再開にはトークン・returnTo・参照元を送らない計測設計が必要。静的旧LP/SEO側の独立した計測まで変更したわけではない。
