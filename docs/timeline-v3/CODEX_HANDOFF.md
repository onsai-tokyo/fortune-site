## 2. 作業一覧

### A. ひとりの時系列（`IMPLEMENTATION.md` §8）
1. `timelineV3/` 一式を配置し（v3 の関数は `timelineV3/index.ts` か `couple.ts` から読み込む。`signals.ts` 単独で `partnerBirth` を渡すとエラー）、`astrology.patch` を当てる（既存関数3つに `export` を付けるだけ）。
2. `ReportCard` に `timelineV3Calculation` を追加、フラグ `ANNUAL_READING_ENGINE=timeline3` で `replaceTimelineV3()` に切り替え。
3. 保存済み鑑定書は `refreshSavedTimelineV3Cards(cards, snapshot, 今の年, lifeEvents, partnerSince, partnerKind, partnerBirth)` で再表示（DBの文章は書き換えない）。
4. 入力の追加（すべて任意）：
   - `relationshipStatus`：プロフィールの「今の状況」（交際中／相手はいない／既婚／答えない → `partnered`／`single`／`married`／null）。DB・API・iOS。
   - `lifeEvents`：年表（`EVENTS.md`。`life_events` テーブル・API・iOS・同意）。
   - `partnerBirth`（v2.24）：同じ相手の出生情報（`birth_data.partner`、海外生まれなら `birthTimeZone` も）。窓の年の一文を二人の運気で選ぶのに使う。カードには保存されない（窓の年の向き `partnerTones` だけが計算メタに残る）。
   - `partnerSince`・`partnerKind`：ふたりの時系列に登録した相手の「出会った年」（`couple_timeline_settings`）と、その相手のラベルの種類。新しい画面は不要。使うのは恋愛のラベル（片思い・お付き合い中・婚約中・夫婦・復縁希望・元恋人）の相手（友人・親は使わない）。複数あるときは、お付き合い中・婚約中・夫婦の相手を優先し、その中で出会った年が一番新しい相手。いなければ、復縁希望・元恋人・片思いの中で出会った年が一番新しい相手。`partnerKind` はラベルから：片思い→`crush`、お付き合い中・婚約中→`partnered`、復縁希望・元恋人→`former`、夫婦→`married`（v2.23。窓とその中の判定〈1点でも動く年〉は交際中と同じで、ラベルごとに違うのは文面）。該当がなければ渡さない。
5. 契約チェック（`contract.ts`）に v3 の分岐。
5b. `backend/package.json` の `test` に `src/lib/report/timelineV3/timelineV3.test.ts` を追加する（今の `npm test` には入っていない）。
6. iOS：`sections` をそのまま表示。新しいタグの色（下の §4）。

## 3. 決まっていること（会話で合意した内容の全体）

### ひとりの時系列
- **判定の土台は人生の時期**（v2.16）：結婚から3〜7年／交際の始まり（年表、または `partnerSince`）から1〜3年／それ以外で26〜34歳。v2.23：登録した相手の出会った年は、片思い・復縁希望・元恋人・夫婦でも窓の起点に使う（窓の中の判定は交際中と同じ）。ラベルごとに文面を変える（片思い「思いを伝えるのか、距離を保つのか」、復縁・元恋人「近づくのか区切るのか」〈一緒にいる前提の言い方はしない〉、夫婦「一緒の暮らしの形など」〈結婚の話はしない〉、1年目はどれも「出会ってまだ間もないこの年は」）。窓の中では関係の点1点でも「関係が動く年」、2点以上で「大きく動く年」。
- **占術**（四柱推命・インド占星術）はその年の意味と書き分けに使う：R1（木星・金星のアンタルダシャー）、R2（日支の冲刑害破、1点）、R3（パートナーの星との干合）、R5（天喜、2点）。R4は0点。
- **婚期**：交際中・関係が動く年で「点＋窓の加点＋7室のダブルトランジット」≥3 の年だけ。v2.19 の「交際の窓の中で1年も出なければ一番点の高い年を婚期にする」補完は v2.25 で削除（362人で偶然と同じ 0.98倍だったため、VALIDATION.md §1n）。交際年数による「#関係の形が決まる時期」のタグと文は残す。
- **大きく動く年は両方向で書く**（v2.18）：婚期として示す年を除き「始まり・深まり」と「区切り」が重なる書き方（大きな年が始まりか終わりかを見分ける目印はデータで見つからなかったため）。
- **文章**：本人の性質（v2.11、`personalParts.json`）、年表の言い直し（v2.13）、人生の時期の一文（v2.16。長いときも削らない）、1年1段落（約190〜300字）が標準。
- 出生時刻なしは10年の流れを正午で近似し、文章だけに使う（v2.10）。

- **窓の年の一文は運気に合わせる**（v2.24）：「関係が始まって◯年がたつこの年は〜」の文を、その年の運気の向き（進む・見直す・両方・穏やか）で選ぶ。登録した相手の生年月日があれば二人の運気（ふたりの時系列と同じ判定）、なければ本人の運気。

### ふたりの時系列
- **判定**：二人の点数の判定（both／self／partner／trust／quiet）。時期の窓の中では1点で動く年。離婚した夫婦75組で離婚の年を1.77倍拾う。
- **時期の窓**（v2.21）：交際中・婚約中は出会いから
  - 1年目「#出会いが深まる時期」：段落を「出会ってまだ間もないこの年は〜」から始め、問いは出会いの印象（v2.21.1）。
  - 2〜3年目「#関係の分かれ道」：結婚か別れのどちらかが最も起きやすい山。ヒントは二人の運気の向きで選ぶ（v2.24）。
  - 4年目「#関係の形が決まる時期」。
  - 片思い・復縁希望・元恋人・夫婦（年表に結婚がない場合、または年表の結婚の年まで）も、出会いから同じ1〜4年の窓とタグを使い、文面とヒントをラベルに合わせる（v2.23）。夫婦の2〜4年目のタグは「#暮らしの形が固まる時期」。夫婦の出会いの窓では「動く年」への昇格と「揺れやすい年」は使わない（結婚前の年が多いため。離婚夫婦75組の1.77倍は変わらない）。
  - 夫婦は年表の結婚から3〜7年「#関係を見直す時期」。
- **窓の年の一文とヒント**（v2.24）：二人の運気の向き（進む・見直す・両方・穏やか）で文を選ぶ。2〜3年目のヒントも向きに合わせる。タグは人生の時期で決まるので変えない。
- **婚期**：点数で出る年だけ（交際の窓の中は3点以上）。v2.19 の「窓の中で必ず1年」は、著名人カップル180組で偶然と同じだったので廃止（v2.21）。
- **現れ方の文は、ひとりの時系列の文をそのまま使う**（v2.20）：二人それぞれの文脈に出会った年を `partnerSince` として入れ、あなたの同じ年の文（相手だけが動く年は相手の文）を使う。ふたりとひとりで読みが食い違わない。
- **揺れやすい年は夫婦だけ**（v2.21）：交際中の別れには効かなかったため。年表に出会った後の結婚があれば、結婚の年までは出さない（v2.22。根拠は結婚期間の中の比較のため）。「別れやすい」「離婚しやすい」とは書かない。
- 片思い・元恋人は一緒の暮らしを前提にしない文、友人・親は恋愛のタグを出さない。

### 検証で分かったこと（`VALIDATION.md`）
- 四柱推命・インド・紫微斗数・西洋・九星・六星・宿曜・数秘など約230個の目印は、年齢だけで当てるのと同じ精度で、再現しなかった。判定に使わない。
- 当たるのは人生の時期：結婚の中心は27〜40歳、交際から結婚までの中央は3年、結婚から離婚までの中央は6年、交際から結婚・別れまでは1〜4年目が約7割。
- 表示は「予言」ではなく振り返りと心構えのための読み物。タグは「候補」。

## 5. 変えてはいけないもの
- 判定ロジック（`signals.ts`・`couple.ts` の判定部分・`vedic.ts`）と点数・閾値。
- 原稿 JSON（`parts.json`・`depthParts.json`・`areaParts.json`・`personalParts.json`・`eventParts.json`・`pairParts.json`）。直すときは `MANUSCRIPT_GUIDE.md` の手順で、期待出力を再生成。

- 実在の人の出来事（年表）や、検証に使った著名人のデータを、コード・テスト・期待出力・資料に入れない（資料には集計の数字だけ）。サンプルの生年月日は、元のリポジトリの既存テストで使われているものと同じで、出来事は架空。
