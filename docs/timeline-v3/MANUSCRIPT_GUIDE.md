# 時系列鑑定 v3 原稿ガイド

鑑定文の部品（`backend/src/lib/report/timelineV3/data/parts.json`）を書く・直す・増やすときのルールです。Claude で原稿を拡張するときは、このファイルと `parts.json` を渡してください。

## 1. 全体の考え方

- 1年分の文章は部品の組み合わせです。部品は「その年の色（十神）」「主題（関係・信頼・仕事・住まい・兆し）」「状況（交際中・相手なし・既婚・未入力）」「節目」「章」「根拠」に分かれます。
- 文章は**主題とその複数の現れ方**を書きます。出来事を当てる書き方はしません。
- 語り口はオーナー方針の**肯定的な並列**です。「〜の形で表れることがあります。〜の形で表れることもあります。」

## 2. 必ず守ること

| ルール | 理由 |
| --- | --- |
| 本文に占術の専門用語を入れない（`jargon.ts` の一覧。特に単字の「冲」「刑」「害」「破」は、「利害」「突破」「障害」のような普通の言葉にも含まれるので避ける。「太陽」「大運」も不可） | 契約チェックとテストで落ちる。専門用語は根拠欄（`evidence.detail`）にだけ書く |
| 他人の気持ちや事実を断定しない（×「裏切られます」「相手は浮気しています」） | 誠実さと安全のため |
| 静かな年に大きな出来事（転職・結婚・引っ越し）を書かない | 年ごとのメリハリが信頼感の源 |
| 健康・妊娠・生死・お金の判断に触れない | AI鑑定書と同じ方針 |
| 「必ず」「絶対」「確実」を使わない | 保証表現の禁止 |
| 18歳未満向け（`youth`）の文に恋愛・結婚の語を入れない | 未成年への配慮 |
| 同性・異性を前提にしない（「男性との縁」ではなく「パートナーとの縁」） | 多様な利用者 |
| 各文は「。」で終える。1文40〜70字が目安 | 組み立て時に文をつなぐため |

## 3. 部品ごとの書き方

| キー | 役割 | 形 | 例 |
| --- | --- | --- | --- |
| `tenGods.*.light[3]` | 静かな年の最初の文。その年の良い面 | 「〜が主題になる年です。」で終える（過去の年は自動で「年でした。」になる。テストで確認） | 自分の意思や裁量、対等な関係が主題になる年です。 |
| `tenGods.*.shadow[3]` | 気をつけたい面 | 「〜形で表れることもあります。」 | 周りとぶつかる形で表れることもあります。 |
| `tenGods.*.undertone[3]` | 主題がある年に添える色 | 「〜も、この年のテーマです。」など | |
| `tenGods.*.advice[3]` | 過ごし方 | 行動が一つ浮かぶ具体性 | 楽しめることを一つ決めて続けると… |
| `tenGods.*.leads[3]` | 見出しの前半 | 連用形で終える（「〜し」「〜ながら」「〜て」）。後ろに「、＋後半」がつく | 人とのつながりが広がり |
| `tenGods.*.quietHeadlines[3]` | 静かな年の見出し | 「〜年」で終える。25字以内 | 肩の力を抜き、心地よい距離感を探す年 |
| `tenGods.*.partnerNote` | パートナーの星の年の一文 | 性別キー（female/male）ごと。「あなたにとっては、〜星の年でもあります。」 | |
| `tails.*[3]` | 見出しの後半 | 「〜年」で終える。前半のどれと組んでも自然になること | 関係が動き出す年 |
| `leads.*[3]` | 主題の導入文 | 「この年は、〜時期です。」で終える（過去形は自動。テストで確認） | |
| `manifestations.*.*[6]` | 現れ方 | 「〜形で表れることがあります／こともあります。」（語尾は組み立て時に自動で整う）。**並び順に意味がある**：0と3＝始まり・前進、1と4＝深まり・見直し、2と5＝区切り・距離。新しく足すときもこの位置を守る | |
| `milestones.*[3]` | 節目の文 | 2文以内。3種は**1文目を変える**（年ごとに入れ替わるため） | |
| `chapters.*` | 章の文 | `title` は「〜10年」「〜時期」、`body` は1文 | |
| `evidencePlain.*` | 根拠の平易な説明 | `{start}` `{end}` `{count}` `{month}` `{year}` は自動で埋まる | |

見出しは「前半（十神）×後半（主題）」で組み立てるため、**新しい前半や後半を足したら、全組み合わせを声に出して読んで**不自然なものがないか確かめてください（10×3×各後半3）。

## 3-1b. 本人の性質の原稿（`personalParts.json`、v2.11）

| キー | 役割 | 形 |
| --- | --- | --- |
| `stem.{日干}.{系統}[3]` | その年が本人の性質にどう響くか | 「（日干の人物像）あなたが／に／を、〜年です。」。1文、です・ます。日干ごとの人物像（甲＝まっすぐ成長する開拓者、乙＝柔軟な調整役、丙＝場を明るくする表現者、丁＝静かな情熱の洞察者、戊＝揺るがない守護者、己＝人と資源を育てる実務家、庚＝決断と変化の実行者、辛＝価値を磨く専門家、壬＝流れを読む戦略家、癸＝感受性の探究者）は自己鑑定と合わせる。3種は別の切り口にする |
| `stem` の系統 | self＝仲間・自立・競い合い、expr＝表現・楽しみ・問い直し、wealth＝成果・お金・行動範囲、duty＝責任・役割・決まり、learn＝学び・支え・休息 | |
| `structure.{月令の系統}.{年の系統}[2]` | 才能の土台とその年の組み合わせ | 1文、です・ます。同じ系統どうし（例：duty×duty）は「持ち味が強く出る一方の偏り」を書く |

- 性質の文には「あなた」をちょうど1回入れ、「相手」は使わない（ふたりの時系列で「あなた」を「相手」に置き換えて使うため）。
- 単字の用語（冲・刑・害・破）を含む語は使わない（例：「型を破る」→「型にとらわれない」）。テストで確認。
- 過去の年は語尾が自動で「でした・ました」になるので、どちらでも自然に読める文にする。

## 3-3. ふたりの時系列の原稿（`pairParts.json`）

| キー | 役割 | 形 |
| --- | --- | --- |
| `leads.*[3]` | 主題の導入文（both / self / partner / trust / quiet / friend） | 「この年は、〜時期です。」。self は「あなた」、partner は「相手」を主語にする |
| `tails.*[3]` | 見出しの後半 | 「〜年」。前半（あなたの十神の書き出し）と組んで自然になること |
| `manifestations.move/trust.{partnered,married,crush,former}[9]` | 二人の間に表れること | 9文の位置の意味：0・3・6＝始まり・前進、1・4・7＝深まり・見直し、2・5・8＝区切り・距離（本人の時系列の6文と同じ並びに、3つ目の組を足したもの）。婚約中は partnered を使う。`friend`・`quiet`・`meeting`・`apart.manifestations` も9文 |
| `manifestations.quiet[6]` / `friend[6]` | 静かな年／友人・親 | 恋愛の語を入れない（friend） |
| `colorNoun.{十神}` | 「あなたは〇〇、相手は〇〇が主題になる年です。」の〇〇 | 名詞句 |
| `evidence.*` | 根拠 | `{who}` に「あなた」「相手」が入る |

片思い・元恋人の文は、**相手の気持ちや復縁を約束しない**。「きっかけが生まれる」「区切りがつく」の両方向を必ず並べる。

## 3-3b. 動き方の質（`parts.json` の `qualities`、`pairParts.json` の `qualitySentence`）

| 質 | 判定 | 書く内容 | 現れ方の先頭 |
| --- | --- | --- | --- |
| grow（育つ） | パートナーの星の期間 | 縁が訪れる・育つ・深まる | 始まり |
| shake（揺れる） | 配偶者の座が揺さぶられる | 今の形が揺れ、組み替わる。大切なものがはっきりする | 区切り |
| mixed（重なる） | 上の2つが同じ年 | 始まりと見直しが同時に来る。変化の幅が大きい | 始まり→区切り |
| pull（引き合う） | パートナーの星との結びつき | 誰かとの引き合い、周りの人の影響 | 深まり・見直し |

`sentence` は「この年の流れ」の2文目に入る（主題の導入文と十神の文の間）。導入文・十神の文と同じ語を使わない。揺れるの文も「壊れる」「失う」などの否定的な断定をせず、「組み替わる」「はっきりする」と書く。

## 3-4. 校正で決めたこと

- **見出しの前半（十神）と後半（主題）で同じ語を使わない。** 組み合わせは10十神×3×後半の全種で約1,300通りあるので、足したら全組み合わせを機械的に確認する（2字以上の漢字語の重複を探す）。
- **過去の年は、振り返りの問いを出す。** 「〜しておくと進めやすくなります」のような未来向けの助言は、今年以降の年だけ。
- **「10年単位の流れ」は大運にだけ使う。** インド占星術の大周期は6〜20年なので、両方を指すときは「人生の大きな流れ」。
- **関係のラベルは「今の状態」。** 出会った年や過去の年に、今の状態（元恋人など）を当てはめない。

## 4. 増やすときの手順（Claude での拡張）

1. Claude に、このガイドと `parts.json`、必要なら `fixtures/nagoya_1995_female.json`（出力例）を渡す。
2. 依頼例：「`tenGods` の各 `leads` と `quietHeadlines` を3つから5つに増やして。ガイドのルールを守って」。
3. 戻ってきた `parts.json` を置き換える。変種を3以外の数にしたら、`compose.ts` の `pick3`/`tail3`（と現れ方の `pickPossibilities`）の剰余と、テストの件数チェックを合わせる。
4. テスト：`npx tsx --test src/lib/report/timelineV3/timelineV3.test.ts`。用語混入・長さ・重複の失敗を直す。
5. ゴールデン再生成：`npx tsx src/scripts/generateTimelineV3Fixtures.ts`。差分を読んで意図どおりか確認する。
6. `parts.json` の `version` を上げる（例：`timeline-v3-parts-1.2`）。

## 5. 増やしてよいもの・検証が必要なもの

- **`areaParts.json` の約束**：`rel`・`work`・`life` の各文は1文目を説明、2文目を助言にする（過去の年は1文目だけを使い、`relPast` などの振り返り文を添える）。`relPast` などは、同じ十神の別の変種の1文目と内容が重ならないように書く（組み立て時に次の変種から取るため）。`closing`・`workClosing` は、当時の状況に依存するので過去の年には出ない。
- **`depthParts.json` の約束**：`combo` の各文は1文目を説明、2文目以降を助言にする（過去の年は2文目以降の助言が自動で落ちる）。`continuity` は1文目に前年との違いを書く。どちらも「昨年」「10年」以外の年や月の数字を書かない（数字は組み立て時に入る）。
- **自由に増やせる**：言い回しの変種、状況（未入力・既婚など）ごとの現れ方、年齢帯の書き分け、章の文。
- **検証が先に必要**：新しい主題（例：「健康」「お金」の時期）、新しいタグ、点数や閾値の変更。判定を変えずに文章だけ足すと、根拠のない主張になります。`VALIDATION.md` の手順を通してから、判定と原稿を一緒に追加してください。
