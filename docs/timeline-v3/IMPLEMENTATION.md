**新規入力の追加（§8-6）**：プロフィールに「今の状況」＝「交際中 / 相手はいない / 既婚 / 答えない」。保存値は `partnered` / `single` / `married` / null。

## 3. 年の定義

- 表示の単位は**西暦の年**（`turning-year-YYYY`）。
- 四柱推命のシグナルは、その年の**立春から翌年の立春**までの干支（既存 `pillars[cycleIndex(year)]`）で判定する。1〜2月の出来事は前年の干支に属する（既存仕様と同じ）。
- インド占星術のシグナルは、**日本時間の1月1日〜12月31日**との重なりで判定する（R1は90日以上）。
- 出生時刻は日本時間。`resolveSpouseTimeZone(input) === 'Asia/Tokyo'` のときだけインド占星術を使う。

## 4. 計算

### 4-1. 四柱推命
既存 `annual3600/engine.ts` の `natalContext()` をそのまま使う（命式4柱、大運 `decades`。大運は出生時刻と性別があるときだけ算出される）。十神は `calcTenGod`。

**出生時刻がない人の大運（v2.10）**：大運の干支は月柱で決まるため、時刻がなくても月柱が1つに決まる日（節入りの日以外）なら確定する。変わるのは開始日だけで、0:00生まれと23:59生まれの差は約4か月（1,162例で中央値122日・最大126日、干支の違い0件）。`timelineContext()` は性別があり月柱が決まる場合に、**正午で計算した大運**を `natal.decades` に入れ、`decadesApprox = true` にする（誤差±2か月）。`annual3600` の動作は変えない。近似の大運は次にだけ使う：
- 「10年の流れの中で」の文、1段落版の組み合わせ文、追い風・向かい風の大運の票、ふたりの時系列の10年の流れ。
- 切り替わる年は「この年の前後で、10年ごとの流れが〜に切り替わります」と月を出さずに書く（`depthParts.timing.daiunChangeApprox`＋`daiunApproxNote`）。

近似の大運は**判定には使わない**：章の開始（`chapterStarts`）と人生の転機を作らず、仕事・住まいの上限の窓も年齢の10年区切りのまま。著名人で試すと、近似の大運から作った人生の転機は 時刻なし52人で0.89倍・同じ20人を時刻なしにして1.77倍と割れたため（VALIDATION.md §1d）。このため v2.10 で判定結果（テーマ・強さ・タグ）は変わらない。

### 4-2. インド占星術（`vedic.ts`）
- 黄経：`GeoVector(body, t, aberration=true)` を `Rotation_EQJ_ECT(t)` で**真黄道（of date）**へ回転し、`SphereFromVector().lon`。
- アヤナムシャ：既存 `lahiriAyanamsha(t)`（J2000で23.85675°、年50.290966″）。
- ナクシャトラ：`floor(月のサイデリアル黄経 / (360/27))`。支配星の順：Ketu, Venus, Sun, Moon, Mars, Rahu, Jupiter, Saturn, Mercury（年数 7,20,6,10,7,18,16,19,17）。
- ヴィムショッタリ：出生時の残り＝(1−ナクシャトラ内の経過割合)×大周期年数。**1年＝365.25日**（`VIMSHOTTARI_YEAR_DAYS`）。小周期の長さ＝大周期年数×小周期年数/120。
- ラグナ：既存 `tropicalAscendant(t, 緯度, 経度)` − アヤナムシャ。座標は既存 `resolveCapital(birthplace)`（都道府県庁所在地）。解決できなければラグナなし。
- ダブルトランジット（家 H）：ホールサイン。各月15日12:00 JST に、木星が「H室の星座」または「H室の支配星の出生時の星座」に 0/4/6/8 番目の関係（合・5・7・9のアスペクト）、かつ土星が 0/2/6/9 番目（合・3・7・10）の関係にある月を数え、**3か月以上**で成立。

**要確認（オーナー）**：アヤナムシャと年の長さは、オーナーが使っている参照ソフト（Jagannatha Hora など）と、サンプル3件のダシャー開始日を突き合わせて一致させる。ずれが1か月以上あれば `VIMSHOTTARI_YEAR_DAYS` を 365.2425 などに合わせる。Swiss Ephemeris は AGPL/商用ライセンスのため、組み込む場合はライセンス確認が必要。

## 6. 判定

0. **人生の時期（v2.16、`lifeStage()`）**：年表の結婚から3〜7年は `married`、交際の始まりから1〜3年は `dating`、それ以外で26〜34歳は `age`。年表はその年より前の出来事だけを使う。窓の中では、関係点1点でも「関係が動く年」。関係の年は、関係点2点以上なら `major`、それ以外は `active`。婚期の判定では `dating`・`age` の窓を+1点として数える。（v2.19〜2.24 にあった「交際の窓で婚期が出なければ一番点の高い年を婚期にする」補完は、v2.25 で削除。）
1. **関係点** `rel = R1+R2+R3+R5`（R4は0点）。
2. **主題**（上から最初に当てはまるもの）：R2とR3が両方 → `trust`／rel≥2 → `relationship`／仕事候補に選ばれた → `career`／住まい候補に選ばれた → `move`／rel=1 → `hint`／それ以外 → `quiet`。
3. **強さ**：rel≥4 `major`、2〜3 `active`、1 `hint`、0 `quiet`。仕事か住まいの候補に選ばれた年は最低 `active`。
4. **上限つきの候補**：仕事は点2以上、住まいは点2以上。**窓**＝その年の7月1日を含む大運の10年（大運がなければ年齢の10年区切り）。窓の中で点の高い順→窓の開始に近い順→早い年の順に、仕事は3年まで、住まいは2年まで選ぶ。窓は表示範囲に関係なく固定なので、1年だけ作っても結果は同じ。
5. **人生の転機**：章の開始がある年は必ず。加えて、`major` かつ仕事か住まいの候補の年を、窓の中の人生の転機が2年になるまで選ぶ（章の年を優先）。
6. **婚期**：18歳以上、`relationshipStatus = partnered`、主題が `relationship`、`rel + DT7 + 窓の加点（dating・age の窓で+1）` ≥ 3。この条件を満たした年だけが婚期（v2.19〜2.24 の補完は v2.25 で削除）。
7. **年齢帯**：13歳未満 `child`、18歳未満 `teen`、それ以上 `adult`。18歳未満は恋愛の語彙・婚期・恋愛タグを使わず、友人関係の語彙（`youth`）に置き換える。表示範囲は現行と同じく18歳以上から始まるため、通常は出ない。

## 7. 文章の組み立て（`compose.ts`）

**本人の性質による個別化（v2.11、`personal.ts`）**：18歳以上の年に、次の2文を作る。
- 性質の文：日干（10）×その年の年干の十神の系統（比劫・食傷・財・官・印の5）×3種。日干ごとの人物像は自己鑑定の `DAY_STEM`（`deterministicReport.ts`）に合わせてある。
- 土台の文：月支の本気（月令）の系統（5）×その年の系統（5）×2種。月柱が決まらない人（節入りの日で時刻なし）は出さない。
- 種類は「それより前の18歳以上の年で、同じ系統の年が何回あったか」で回す。10年の中の陰陽の2年は別の文になり、10年後にも別の文が出る。
- 詳細版では「現れ方」の次に「あなたにとってのこの年」の節を置く。1段落版では、性質の文を十神の「添える色」（`undertone`）の代わりに入れ、土台の文を関係以外の年の「響く場所・気をつけたい面」の代わりに入れる。長すぎるときは、先に分野の一般的な文を削る。

| 要素 | 作り方 |
| --- | --- |
| 変種の選び方 | `i = floor(year/10) % 3`：十神の文（見出しの前半・静かな年の見出し・良い面・気をつけたい面・添える色・過ごし方）と信頼の年の過ごし方。同じ十神は10年ごとに巡るので、**30年以内に同じ十神の文は出ない**。`j = year % 3`：見出しの後半・主題の導入文・節目の文。**隣り合う年で同じにならない**。現れ方は6文から `pickPossibilities()` で選ぶ（下記） |
| 見出し | 主題がある年＝`tenGods[十神].leads[i]` ＋「、」＋`tails[主題][強さ][j]`。静かな年＝`quietHeadlines[i]` |

## 8. 配線手順（Codexの作業）

各ステップ後に `npm test` と v3 テストを実行する。

1. **ファイル追加**：v3 の関数は必ず `timelineV3/index.ts`（またはふたりの時系列は `couple.ts`）から読み込む。`signals.ts` だけを読み込んで `partnerBirth` 付きの文脈を作ると、二人の運気の計算が登録されていないためエラーになる（v2.24）。§1 のファイルを配置し、`astrology.patch` を適用（`resolveCapital`・`lahiriAyanamsha`・`tropicalAscendant` に `export` を付けるだけ）。
2. **型**：`reportCards.ts` の `ReportCard` に任意項目を追加する。
   ```ts
   timelineV3Calculation?: { version: string; partsVersion: string; input: import('./report/timelineV3/signals.js').TimelineV3Input; nowYear: number; decision: Record<string, unknown> }
   ```
3. **フラグ**：`selfReportOptions.ts` で `ANNUAL_READING_ENGINE=timeline3` のとき `annualEngine: 'timeline3'`。`selfReportPipelineTag` に `|${TIMELINE_V3_VERSION}` を追加。
4. **生成**：`buildSelfReport.ts` で
   ```ts
   options.annualEngine === 'timeline3' ? replaceTimelineV3(generatedReport, input, japanDateParts().year)
   : options.annualEngine === 'catalog3600' ? replaceAnnual3600(...) : replaceTimingCards(...)
   ```
   `input` に `relationshipStatus`・`lifeEvents`・`partnerSince`・`partnerKind`・`partnerBirth` を渡す（`ReportInput` に任意項目を追加。値の取り方は §8-6）。
5. **保存済み鑑定書**：`savedTimelineCards.ts` で、フラグが `timeline3` のとき `refreshSavedTimelineV3Cards(cards, snapshot, 今の年, lifeEvents, partnerSince, partnerKind, partnerBirth)` を使う（`lifeEvents`＝今の年表、`partnerSince`・`partnerKind`＝今の設定の出会った年と種類）。スナップショットに `relationshipStatus` を保存する。**今の状況はスナップショットの値を使う**（鑑定書はその時点の状況で読む、という現行の方針どおり）。`partnerKind` を渡せば、状況に関係なく出会った年の窓が開く。渡さないときは、保存時に「交際中」だった鑑定書だけに効く。DBの原稿は書き換えない（現行と同じ方針）。
6. **入力項目**：
   - DB：プロフィールと鑑定スナップショットに `relationship_status text null`（`partnered|single|married`）。Supabase のマイグレーションを追加。
   - API：プロフィール更新・鑑定作成の検証で `parseRelationshipStatus()` を使う。
   - iOS：`ProfileView` に「今の状況」（交際中／相手はいない／既婚／答えない）。説明文「時系列の文章の書き分けにだけ使います」。
   - **年表と出会った年（v2.13・v2.19）**：`buildSelfReport.ts` と保存済み鑑定書の再表示で、本人の年表（`life_events`、`EVENTS.md`）を `lifeEvents` に、登録中の相手の出会った年と種類（`couple_timeline_settings`、§2 の選び方）を `partnerSince`・`partnerKind` に、その相手の出生情報（`birth_data.partner`、`birthTime: null` は省く）を `partnerBirth` に入れる。どちらも新しい画面は不要（年表は `EVENTS.md` の画面、出会った年は既存のふたりの時系列の設定）。
   - 生まれ時刻の入力欄の説明に「母子健康手帳の出産の記録に載っています。時刻があると、時期を月単位で読めます。」を追加。
7. **契約チェック**：`contract.ts` に v3 用の分岐を追加する。
   - `card.timelineV3Calculation?.version === TIMELINE_V3_VERSION` のとき、`timelineV3CardIsValid(card)` が false なら `SCHEMA` 違反。
   - セクション数は4〜12（18歳以上は「10年の流れの中で」「この年の時期」「この年が響く場所」、分野ごとの3段落、「前後の年とのつながり」が入る）、各本文は600字以内（現行の timing 用の 1〜2 / 220字の制限は適用しない）。
   - 用語チェック（`containsJargon`）は現行どおり全本文に適用。
8. **iOS表示**：カードは `sections` をそのまま表示すれば動く。追加対応は次の2点だけ。
   - 5セクション目（「これからの大きな流れ」）が来る年がある。
   - 新しいタグ（上表）の表示色。`#人生の転機` は既存。
9. **切り替え**：ステージングで `ANNUAL_READING_ENGINE=timeline3`。サンプル7件と社内アカウントで表示確認後、本番へ。問題があれば `catalog3600` に戻す。

## 11. 既知の制約・未決事項

- R5（天喜）は時刻がなくても使える候補15個の中から選んだため、偶然の当たりを含む可能性がある。3つ目のデータで1.3倍を下回ったら外す。
- 男性のR1（金星の期間）は未検証。根拠の強さはBで、点は2。
- 仕事・住まいの判定は伝統的なルールで、検証データが足りない（仕事5件・引っ越し3件で試しただけ）。タグは「候補」と表記している。
- 過去の年は語尾だけ過去形にしている。保存済み鑑定書は開いた年を基準に再表示されるため、年が変わると語尾が変わる（意図した挙動）。
- ふたりの時系列は `COUPLE.md` の方式で置き換える。「二人の動く年」は離婚した夫婦75組で離婚の年を1.77倍拾う（§1g〜1h）。交際中のカップル180組では、婚期の年・動く年は偶然と同じで、出会いから1〜4年の窓（結果の約7割）が効く（§1m）。

## 表示スタイル（v2.4〜）：1年1段落（アプリの標準）

アプリの時系列は **1年を1つの段落（約200〜300字）** で表示する（`style: 'simple'`、既定）。判定・原稿は詳細版と同じで、組み立てだけが違う。

| 順 | 1段落に入れる文 | 使う部品 |
| --- | --- | --- |
| 1 | 主題の導入（静かな年は十神の良い面） | `leads`／`tenGods.*.light` |
| 2 | 十神の添える色（兆しの年は良い面） | `tenGods.*.undertone`／`light` |
| 3 | 10年の流れの中でこの年が持つ意味（大運×年の十神の組み合わせ文の1文目。「n年目」の文は1段落の版では使わない） | `decade.comboText` |
| 4 | 関係・信頼の年：現れ方を2文。それ以外：節目の文（婚期・仕事・住まい）か「この年が響く場所」の1文目（なければ十神の気をつけたい面）＋「恋愛・人との関わり」の1文目 | 各セクションの先頭 |
| 5 | 人生の転機の文、なければその年の変わり目の中身（「この年の時期」で選んだ変わり目の文そのもの。例：「11月ごろには、〜時期に入ります。」）。出生時刻がなく中身がないときだけ「{月}ごろが、この年の流れの変わり目です。」 | `timing.turnText`／`depthParts.simple` |
| 6 | 過ごし方（過去は振り返りの問い）1文 | 十神の `advice`／`reflection` |

- 190字に満たない年は、追い風・向かい風の一文を過ごし方の前に足す。320字を超える年は2番を落とす。
- 「主題」は「テーマ」に言い換える（`depthParts.simple.plain`）。可能性の文は、最初だけ「〜ことがあります」、以降は「〜こともあります」。
- カードの形：`summary` ＝ 段落、`sections` ＝ [「この年の鑑定」（段落）, 根拠と期間]。見出し・タグ・根拠・判定のメタは詳細版と同じ。メタに `style: 'simple'` を記録し、`timelineV3CardIsValid`・`refreshSavedTimelineV3Cards` は同じスタイルで作り直す。
- ふたりの時系列も同じ（`buildCoupleTimelineV3({ ..., style })`、既定 `simple`）：導入（出会った年は「二人が出会った年です。」）、動き方の質、二人の色、現れ方2文、結びつき・章の文、二人の変わり目が重なる月、ヒント（出会った年は専用の問い・ヒント）。190字未満なら「あなたは、〜。相手は、〜。」を足す。
- **タイトル（1年1段落の版）**：その年のテーマを10字前後で言い切る（`depthParts.titles`、`shortTitle`）。優先順：婚期（今年以降のみ）＞信頼＞関係（動き方の質ごと：育つ・揺れる・重なる・引き合う）＞仕事（働き方ごと）＞住まい＞章の開始＞兆し（交際中・既婚は今年以降のみ専用の言い方）＞静かな年（十神ごと）。静かな年は `i`（同じ十神の10年後は別の言い方）、それ以外は「生まれてから同じ種類のタイトルが何回目か」で3種を回す。過去の年は、今の交際状況を前提にした言い方（婚期・交際中の兆し）を使わない。本文でも、過去の年の関係の現れ方は「未入力」の文、婚期の節目の文・タグは今年以降だけ（判定のメタ `marriage` はそのまま残す）。
- ふたりの時系列のタイトル：主題の後半（`tails`）だけにする。静かな年は、あなたの十神ごとの `pair.quietTitles`（例：「二人で楽しみを育てる年」）、出会った年は `pair.meeting.tails`。
- 詳細版（セクションごとの長い版）は `style: 'detailed'` で出せる（テスト・原稿の確認用）。タイトルも従来の「十神の書き出し＋主題の後半」のまま。
