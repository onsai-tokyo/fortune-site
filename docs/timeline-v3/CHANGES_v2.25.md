# v2.25 変更内容：ひとりの時系列の「婚期の補完」を削除

ロジック版：v2.25 / `timeline-v3.31`（v2.24 / `timeline-v3.30` からの差分）

## 1. 変更したこと
- **削除**：ひとりの時系列の婚期の補完（v2.19 で追加）。交際の窓（`partnerSince` か年表の交際の始まりから1〜3年）の中で、どの年も通常の条件で婚期にならないとき、窓の中で一番点の高い年を婚期にし、その年を「関係が動く年」に格上げしていた処理。
- **婚期の条件（変更なし）**：18歳以上・`relationshipStatus = partnered`・その年が「関係が動く年」・`関係の点 + 7室のダブルトランジット(+1) + 交際/年代の窓(+1)` ≥ 3。補完の削除後は、これを満たした年だけが婚期。
- **残したもの**：交際年数による時期の窓（「#関係の形が決まる時期」のタグ、窓の年の一文、窓の中で関係の点1点でも「関係が動く年」になる判定）。ふたりの時系列の判定（v2.21 で補完は削除済み）。

## 2. 差分
- コード：`backend/src/lib/report/timelineV3/signals.ts` の `decideYear()`（補完の13行を削除、通常判定の2行に置き換え）。
- テスト：`timelineV3.test.ts` の「v2.19/v2.25 partnerSince」を変更。
  - 旧：窓の中に婚期が必ず1年ある。
  - 新：婚期は「関係が動く年」だけに付く。サンプルには婚期のない窓が実際にある（補完が残っていれば落ちる）。
- 資料：`LOGIC.md`・`IMPLEMENTATION.md`・`COUPLE.md`・`CODEX_HANDOFF.md`・`VALIDATION.md`（§1n を追加）。
- 期待出力：40ファイル中14ファイルが変わる。13ファイルは版の文字列（`timeline-v3.30`→`timeline-v3.31`）だけ。中身が変わったのは1ファイル1年。
  - ファイル：`simple_life_saga_1997_female_partnered.json`。
  - 補完で婚期になっていた年が婚期でなくなり、窓の年の一文の向きが「進む」→「見直す」に変わった（過去の年なので婚期の印は元から表示していない）。
- 全差分：`v2.25_remove_marriage_guarantee.patch`（v2.24 の一式との `diff -ru`。コード・テスト・資料）。
